# Approach Risk ver. 1.1

**Seasonal Learning · Прогноз высоты на заходе · Париж, Хитроу, Франкфурт**

Это развитие [Approach Risk ver. 1.0](https://github.com/steptovictory-dev/Approach-Risk-ver.-1.0). В версии 1.0 исследовались авиационные данные, восстановление траекторий, погодные признаки и прогнозирование ухода на второй круг. Версия 1.1 переходит к наблюдаемой динамике конечного захода: насколько точно простые модели могут предсказать высоту самолета через **30 ± 3 секунды**?

В трех аэропортах сравнили продолжение текущей вертикальной скорости, линейную Ridge и Polynomial Ridge степени 2. **Polynomial Ridge дала наименьшую среднюю ошибку общего теста каждого аэропорта среди проверенных моделей.** Снижение относительно baseline составило **65.2–72.4%**, относительно линейной Ridge **5.4–14.3%**.

**Статус:** исследование завершено 13.10.2026, основная ветка `main`.

[Полный результат](research/RESULTS.md) · [Финальное ревью](FINAL_REVIEW.md) · [Париж](research/lfpg-seasonal-learning/README.md) · [Хитроу](research/egll-seasonal-learning/README.md) · [Франкфурт](research/eddf-seasonal-learning/README.md)

## Главный результат

**MAE** показывает среднюю абсолютную ошибку прогноза высоты. **ft (feet)** означает футы: **1 ft = 0.3048 м**. Например, MAE 20 ft означает ошибку около 6.10 м, а не высоту полета самолета. Меньшее значение лучше.

| Модель | Париж, LFPG 09L | Хитроу, EGLL 09L | Франкфурт, EDDF 07L |
| --- | ---: | ---: | ---: |
| Baseline: постоянная вертикальная скорость | 49.35 ft | 55.95 ft | 72.60 ft |
| Ridge | 20.03 ft | 16.34 ft | 22.23 ft |
| **Polynomial Ridge, степень 2** | **17.16 ft** | **15.45 ft** | **20.87 ft** |
| Huber | 19.57 ft | 16.11 ft | Не обучалась |
| ElasticNet | 17.85 ft | 16.24 ft | Не обучалась |

![Средняя ошибка прогноза высоты: baseline, Ridge и Polynomial Ridge в трех аэропортах](research/eddf-seasonal-learning/figures/03_three_airports.png)

*Каждая панель относится к отдельно обученной модели своего аэропорта. Все модели внутри аэропорта проверены на одинаковых тестовых заходах.*

| Выигрыш Polynomial Ridge | LFPG | EGLL | EDDF |
| --- | ---: | ---: | ---: |
| Снижение MAE относительно baseline | 65.2% | 72.4% | 71.3% |
| Снижение MAE относительно Ridge | 14.3% | 5.4% | 6.1% |
| Ошибка высоты в метрах | 5.23 м | 4.71 м | 6.36 м |

Переход от baseline к обучаемой поправке дает основной выигрыш. Добавление квадратов и взаимодействий признаков дополнительно снижает среднюю ошибку. Это преимущество на общем тесте: в отдельных сезонных подгруппах выигрывают другие модели.

## Что именно прогнозируем

Представим самолет, снижающийся с текущей вертикальной скоростью. Простейший прогноз продолжает это снижение на следующие 30 секунд:

`Будущая высота = текущая высота + вертикальная скорость × время`

Обучаемые модели добавляют поправку по девяти признакам: высоте, текущей вертикальной скорости, изменению высоты в недавней истории, путевой скорости, расстоянию до порога, отклонению от оси полосы, ошибке путевого угла, интервалу до прошлой точки и горизонту прогноза.

| Уровень модели | Что меняется |
| --- | --- |
| Baseline | Продолжает текущую вертикальную скорость; обучение не требуется |
| Ridge | Обучает линейную поправку с регуляризацией |
| Polynomial Ridge | Добавляет квадраты и попарные взаимодействия: 9 признаков преобразуются в 54 |

Целевые высоты берутся из последующих наблюдений без интерполяции. Исторические признаки используют только прошлые и текущие точки. Высота приводится к QNH относительно общей высоты аэродрома; это барометрический прокси, не радиовысота.

## Данные и схема эксперимента

**Только 2025 год. Одна полоса в каждом аэропорту. По пять погожих дней весной, летом и осенью.**

| Аэропорт | Полоса | Дней | Пригодных заходов | Пар наблюдений | Тестовых заходов |
| --- | --- | ---: | ---: | ---: | ---: |
| Париж Шарль-де-Голль, LFPG | 09L | 15 | 553 | 15 931 | 55 |
| Лондон Хитроу, EGLL | 09L | 15 | 5 601 | 166 508 | 1 136 |
| Франкфурт-на-Майне, EDDF | 07L | 15 | 2 634 | 96 714 | 540 |
| **Всего** | | **45 записей «аэропорт-день»** | **8 788** | **279 153** | **1 731** |

Календарные даты между аэропортами могут совпадать. Каждая пара наблюдений связывает исходное состояние с последующей высотой через 27–33 секунды; один заход дает несколько таких пар.

В каждом сезоне первые три выбранных дня используются для обучения, четвертый для валидации, пятый для теста. **Общая модель аэропорта обучается на девяти днях**, параметры выбираются по трем валидационным дням, результат оценивается на трех тестовых днях.

Ошибка усредняется сначала внутри захода, затем между заходами. Каждый заход получает одинаковый суммарный вес при обучении. Плотнее наблюдаемая траектория не получает большего веса только за счет числа точек. Идентификатор борта не является признаком, но борта могут повторяться между днями.

Источники: [ADSB.lol, архивы 2025](https://github.com/adsblol/globe_history_2025), [IEM METAR](https://mesonet.agron.iastate.edu/request/download.phtml), [OurAirports](https://github.com/davidmegginson/ourairports-data). Полоса определяется по геометрии траектории; направление ветра само по себе не подтверждает заход на конкретную полосу.

## Что называем погожим днем

Все условия должны выполняться на всем дневном интервале **08:00–18:00 местного времени**. Проверка идет каждые пять минут по последнему METAR давностью не более 60 минут. Несколько хороших часов недостаточно; остальные часы суток в это определение не входят.

| Характеристика | Условие |
| --- | --- |
| Видимость | Не менее 10 км |
| Потолок облачности BKN/OVC или вертикальная видимость VV | Не ниже 3000 ft, около 914 м, либо подтвержденное отсутствие такого потолка |
| Ветер | Не более 15 kt, около 7.7 м/с |
| Порывы | Не более 25 kt, около 12.9 м/с |
| Температура | От -10 до +30 °C включительно |
| Погодные явления | Нет явлений в погодном блоке METAR, отметок сдвига ветра WS и недавних явлений RE |
| Полнота данных | Сообщение успешно разобрано, необходимые характеристики известны |

Высокая сплошная облачность допускается: погожий не обязательно означает безоблачный. Используется наблюдаемый основной блок METAR, без прогнозных частей TEMPO/BECMG. Это исследовательский фильтр благоприятных условий.

## Больше дней означает лучшее качество?

**Автоматически такого вывода сделать нельзя.** При добавлении дней одновременно меняются объем и состав данных. Кривые обучения показывают, как это влияет на результат при фиксированном тестовом дне и параметрах модели.

![Влияние одного, двух и трех обучающих дней внутри сезона во Франкфурте](research/eddf-seasonal-learning/figures/02_learning.png)

*Здесь модели обучаются отдельно внутри каждого сезона. Это другой состав обучения, чем у общих моделей на девяти днях в главной таблице.*

Например, в EDDF при обучении только на трех осенних днях Ridge лучше Polynomial Ridge: **20.75 против 22.19 ft**. При общем обучении на девяти днях на том же осеннем тесте Polynomial Ridge лучше: **19.71 против 21.41 ft**.

Кривые обучения остальных аэропортов: [LFPG](research/lfpg-seasonal-learning/figures/02_learning.png), [EGLL](research/egll-seasonal-learning/figures/02_learning.png). Сезонные таблицы и подробное обсуждение: [общий RESULT](research/RESULTS.md).

## Как читать результат

Результат поддерживает умеренное усложнение модели **для средней ошибки общего теста каждого аэропорта в выбранных условиях**. Polynomial Ridge выигрывает среди проверенных семейств в семи из девяти сезонных подгрупп. В LFPG летом лучше ElasticNet, осенью Huber; осенью линейная Ridge также немного лучше Polynomial Ridge.

При интерпретации учитываем:

- Это прогноз высотной компоненты; полная трехмерная траектория и вероятность ухода на второй круг в сезонном эксперименте не оценивались
- На сезон приходится один тестовый день. Доверительные интервалы и статистическая значимость не оценивались
- Каждая модель обучена отдельно для своего аэропорта. Перенос готовой модели между аэропортами не проверен; сравнение MAE не определяет сложность аэропорта
- В EDDF проверены только два варианта Ridge и baseline; Huber и ElasticNet там не запускались
- Зима, неблагоприятная погода, другие полосы и другие годы в основное сравнение не входят
- Доступность METAR предполагает задержку 15 минут. COR допущены в EGLL и исключены в LFPG/EDDF; время исторической публикации неизвестно
- Фактический горизонт 27–33 секунды входит в признаки. Результат требует отдельной проверки для онлайн-прогноза строго на 30 секунд
- Исторические NOTAM и эксплуатационная применимость текущей геометрии не подтверждены

## Воспроизведение

Команды выполняются из корня репозитория. Рекомендуется отдельное виртуальное окружение.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Полный путь от получения архивов до обучения описан отдельно для [LFPG](research/lfpg-seasonal-learning/README.md), [EGLL](research/egll-seasonal-learning/README.md) и [EDDF](research/eddf-seasonal-learning/README.md). Получение суточных архивов требует сети, времени и дискового пространства.

При наличии сохраненных данных и моделей результаты проверяются без переобучения:

```powershell
python scripts/verify_project.py
python research/egll-seasonal-learning/scripts/verify_results.py
python research/eddf-seasonal-learning/scripts/verify_results.py
```

Чтение опубликованных отчетов и выполненных ноутбуков не требует локальных исходных архивов. Проверка прогнозов требует локальных данных и моделей; в Git они не включены.
