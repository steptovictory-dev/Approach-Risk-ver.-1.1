# Сколько дней нужно для обучения?

Отдельный эксперимент LFPG 09L: по 7 подходящих дней зимнего месяца, марта, июля и октября 2025 года, всего 28 дней. В январе не хватает погожих дней; по указанию пользователя проверяем февраль, затем при необходимости декабрь. Ветка `research/lfpg-seasonal-learning` создана от `research/lfpg` после исследования 06.

Проверяем, как меняется ошибка при обучении на 1, 2, 3 и 5 днях, и как обучение переносится между месяцами. Для каждого сравнения проверочные дни сохраняются одинаковыми. Дополнительно отделяем увеличение числа примеров от разнообразия дней: сравниваем наборы с одинаковым числом обучающих заходов.

## Какие дни ищем

Одна полоса: LFPG 09L. Полосу определяем по фактическим траекториям, а не по направлению ветра. Минимум 30 пригодных заходов в дневном интервале с хорошей погодой. Правила высотного прогноза сохраняются: история 5–30 секунд, горизонт 30 ± 3 секунды, наблюдения до барометрического прокси 300 ft.

Рабочее определение хорошей погоды для исследования: видимость не менее 10 км, нижняя граница BKN/OVC не ниже 3000 ft или CAVOK, ветер не выше 15 kt, порывы не выше 25 kt, температура от -10 до +30 C. Исключаем осадки, грозы, туман, пыльные/песчаные явления и сообщения о сдвиге ветра. Условия проверяются по наблюдаемой части METAR, без использования TEMPO/BECMG как фактических наблюдений. Это условия отбора исследовательской группы, а не эксплуатационные минимумы.

Для дневного поиска используем 08:00–18:00 местного времени Парижа с учетом перехода на летнее время. По указанию пользователя нужен целиком погожий день: хорошая погода должна покрывать весь этот интервал; каждый включенный заход целиком проходит в подходящей погоде. Погодные интервалы с неизвестными условиями исключаем. Семь дней месяца считаются найденными только после проверки достаточного числа заходов.

## Данные и результаты

- `data/`: исходные METAR, локальные архивы, отобранные траектории и обучающие примеры; исключены из Git
- `notebooks/`: выполненный обзор выбранных дней и дальнейшие обучающие эксперименты
- `reports/`: итоговые таблицы выбранных дней и результатов моделей
- `figures/`: рисунки для ноутбуков
- `scripts/`: получение и подготовка данных

Источники: [ADSB.lol, архив 2025](https://github.com/adsblol/globe_history_2025), [METAR IEM](https://mesonet.agron.iastate.edu/request/download.phtml). Геометрия полос и причинные признаки продолжают предыдущую работу LFPG; происхождение новых исходных файлов хранится рядом с данными.

Дата поиска не выбирается по ошибкам моделей. Неподходящие дни не оформляются в отдельные отчеты. Для последующего обучения нужны сначала подтвержденные 28 дней.

## Что получилось при проверке погоды

Проверены январь, февраль и декабрь 2025 года; дополнительно те же зимние месяцы 2024 года. Даже для дневного интервала 08:00–18:00 ни один зимний месяц не дает семь дней по текущим условиям отбора. Требование хорошей погоды за все 24 часа может только уменьшить эти числа.

| Зимний месяц | Дней в 2025 году | Дней в 2024 году |
|---|---:|---:|
| Январь | 2 | 6 |
| Февраль | 3 | 2 |
| Декабрь | 5 | 3 |

Это предварительные погодные кандидаты: заходы на 09L и их достаточное количество еще не проверены. Для остальных запрошенных месяцев 2025 года по погоде нашлись 8 кандидатов в марте, 15 в июле и 7 в октябре. Полный набор из 28 дней пока не подобран; обучение этого эксперимента не запускалось. Условия отбора сохраняем до решения пользователя о зимней группе.

## Повторить поиск погоды

Из корня репозитория установить зависимости `python -m pip install -r research/lfpg-seasonal-learning/requirements.txt`, затем выполнить `python research/lfpg-seasonal-learning/scripts/select_weather.py 2025`. Аргумент `2024` повторяет дополнительную проверку. Скрипт загружает METAR IEM, сохраняет исходные сообщения и таблицу погодных кандидатов в локальной папке `data/`. При повторном запуске используются сохраненные исходные сообщения.
