# Сколько дней нужно для обучения?

Отдельный эксперимент LFPG 09L: по 5 подходящих дней весны, лета и осени, всего 15 дней. По указанию пользователя зимний пилот оставлен в прежнем виде и не включается в новый сезонный расчет. Используем только 2025 год. Месяц внутри сезона любой: весна март–май, лето июнь–август, осень сентябрь–ноябрь. Ветка `research/lfpg-seasonal-learning` создана от `research/lfpg` после исследования 06.

Проверяем, как меняется ошибка при обучении на 1, 2 и 3 днях, и как обучение переносится между сезонами. Для каждого сравнения проверочные дни сохраняются одинаковыми. Это первое приближенное сравнение, без дополнительных экспериментов по выравниванию числа заходов.

Модели для обучения: Ridge, Huber, ElasticNet и Polynomial Ridge второй степени. Базовый прогноз сохраняет текущую вертикальную скорость. Все модели учат поправку к нему. Подбор параметров компактный: три варианта на семейство, по валидационным дням; проверочные дни не участвуют в выборе модели.

В каждом сезоне последний выбранный день используется для теста, предыдущий для валидации, первые три для обучения. Есть отдельное обучение по сезонам и общее обучение. Межсезонный перенос является сравнением на отложенных днях; общее обучение использует разные месяцы года. Один борт может встречаться в разных днях; его идентификатор не является признаком.

Для кривой обучения сравниваем все четыре модели на 1, 2 и 3 днях. Добавляем дни по порядку дат и берем все пригодные примеры. Одновременно меняются количество примеров и состав дней; результаты описывают их совместный эффект. Параметры модели фиксируются после выбора по валидации полного обучающего набора сезона. Каждый заход имеет одинаковый суммарный вес независимо от числа пар наблюдений.

## Какие дни ищем

Одна полоса: LFPG 09L. Полосу определяем по фактическим траекториям, а не по направлению ветра. Для первого приближенного сравнения берем дни с минимум 10 пригодными заходами и 300 учебными парами в дневном интервале с хорошей погодой. В осенней группе есть дни с 14–19 заходами и примерно тысячей пар; это небольшой набор для чернового сравнения. Правила высотного прогноза сохраняются: история 5–30 секунд, горизонт 30 ± 3 секунды, наблюдения до барометрического прокси 300 ft. Соединение траекторий с METAR выполняется по целым секундам.

Рабочее определение хорошей погоды для исследования: видимость не менее 10 км, нижняя граница BKN/OVC не ниже 3000 ft или CAVOK, ветер не выше 15 kt, порывы не выше 25 kt, температура от -10 до +30 C. Исключаем осадки, грозы, туман, пыльные/песчаные явления и сообщения о сдвиге ветра. Условия проверяются по наблюдаемой части METAR, без использования TEMPO/BECMG как фактических наблюдений. Это условия отбора исследовательской группы, а не эксплуатационные минимумы.

Для дневного поиска используем 08:00–18:00 местного времени Парижа с учетом перехода на летнее время. По указанию пользователя нужен целиком погожий день: хорошая погода должна покрывать весь этот интервал; каждый включенный заход целиком проходит в подходящей погоде. Погодные интервалы с неизвестными условиями исключаем. Дни сезона считаются найденными только после проверки достаточного числа заходов.

## Данные и результаты

- `data/`: исходные METAR, локальные архивы, отобранные траектории и обучающие примеры; исключены из Git
- `notebooks/01_seasonal_days.ipynb`: погода и отбор дней
- `notebooks/02_seasonal_training.ipynb`: модели, влияние числа дней и итоговые выводы
- `reports/RESULTS.md`: итоговые выводы исследования
- `reports/csv/`: подробные таблицы выбранных дней и результатов моделей
- `figures/`: рисунки для ноутбуков
- `scripts/`: получение и подготовка данных

Источники: [ADSB.lol, архив 2025](https://github.com/adsblol/globe_history_2025), [METAR IEM](https://mesonet.agron.iastate.edu/request/download.phtml). Геометрия полос и причинные признаки продолжают предыдущую работу LFPG; происхождение новых исходных файлов хранится рядом с данными.

Дата поиска не выбирается по ошибкам моделей. Неподходящие дни не оформляются в отдельные отчеты. Для последующего обучения нужны сначала подтвержденные 15 дней трех выбранных сезонов. Очередь погодных кандидатов учитывает долю времени с восточным ветром; для весны приоритет отдан мартовским датам рядом с уже готовыми днями. Два мартовских архива загружаются заранее. Фактическая полоса проверяется по траекториям. Три сезона собираются одновременно, поиск каждого прекращается после пяти готовых дней.

## Что получилось при проверке погоды

Проверка всех месяцев 2025 года дала следующие погодные кандидаты для дневного интервала 08:00–18:00:

| Сезон | Погодных кандидатов | Нужно дней с заходами на 09L |
|---|---:|---:|
| Зима | 10 | Оставлена вне нового расчета |
| Весна | 29 | 5 |
| Лето | 45 | 5 |
| Осень | 18 | 5 |

Это предварительный отбор: заходы на 09L и их достаточное количество проверяются отдельно. Новый набор из 15 дней собран; полный расчет трех сезонов выполнен. Осенний пилот также сохранен отдельно. Зимний пилот сохранен, его результаты приведены ниже.

При прежнем зимнем поиске проверка 1 декабря нашла 69 геометрических заходов на 26L и ни одного на 09L. После зимнего пилота поиск зимних дней остановлен по решению пользователя.

## Первые результаты зимнего обучения

Первое обучение выполнено на пяти готовых зимних днях; результаты сохранены в `reports/csv/winter_pilot_*.csv`. Обучение: 10 января, 13 января и 2 февраля; валидация 15 февраля; неизменный тест 21 февраля, 93 захода и 1793 пары. После остановки пользователь разрешил продолжить работу с весной, летом и осенью. Зимнее обучение не пересчитывается.

| Модель | MAE, 1 день | MAE, 2 дня | MAE, 3 дня |
|---|---:|---:|---:|
| Ridge | 24.45 | 22.31 | 19.99 |
| Polynomial Ridge | 23.94 | 23.21 | 22.96 |
| Huber | 18.89 | 20.46 | 21.54 |
| ElasticNet | 19.27 | 18.79 | 19.22 |
| Постоянная вертикальная скорость | 56.43 | 56.43 | 56.43 |

Все ошибки в ft, средние по заходам. Параметры выбраны по валидации трехдневного обучения и фиксированы для остальных размеров. Добавление дней в этом первом расчете улучшает Ridge и Polynomial Ridge, ухудшает Huber; у ElasticNet результат немонотонный.

## Повторить расчет

Из корня репозитория установить зависимости `python -m pip install -r research/lfpg-seasonal-learning/requirements.txt`, затем выполнить `python research/lfpg-seasonal-learning/scripts/select_weather.py 2025`. Скрипт загружает METAR IEM, сохраняет исходные сообщения и таблицу погодных кандидатов в локальной папке `data/`. При повторном запуске используются сохраненные исходные сообщения.

Для проверки фактических заходов выполнить `python research/lfpg-seasonal-learning/scripts/collect_days.py YYYY-MM-DD`. Суточный архив ADSB.lol занимает несколько гигабайт; исходные файлы, их контрольные суммы и извлеченные траектории сохраняются локально в `data/`.

`python research/lfpg-seasonal-learning/scripts/prepare_examples.py YYYY-MM-DD` строит наблюдаемые обучающие пары по прежним причинным признакам. `python research/lfpg-seasonal-learning/scripts/collect_seasons.py` собирает по пять готовых дней весны, лета и осени, затем автоматически обучает модели и выполняет итоговый ноутбук. При нехватке подтвержденных дней обучение не начинается, состояние каждого сезона сохраняется локально в `data/*_collection.json`. Отдельный повтор обучения на уже готовых днях: `python research/lfpg-seasonal-learning/scripts/train_models.py`.

`python research/lfpg-seasonal-learning/scripts/build_training_notebook.py` выполняет ноутбук с таблицей и рисунками после завершенного обучения.
