# Сколько дней нужно для обучения?

Отдельный эксперимент LFPG 09L: по 10 подходящих дней весны, лета и осени, всего 30 дней. По указанию пользователя зимний пилот оставлен в прежнем виде и не включается в новый сезонный расчет. Используем только 2025 год. Месяц внутри сезона любой: весна март–май, лето июнь–август, осень сентябрь–ноябрь. Ветка `research/lfpg-seasonal-learning` создана от `research/lfpg` после исследования 06.

Проверяем, как меняется ошибка при обучении на 1, 2, 3 и 5 днях, и как обучение переносится между сезонами. Для каждого сравнения проверочные дни сохраняются одинаковыми. Дополнительно отделяем увеличение числа примеров от разнообразия дней: сравниваем наборы с одинаковым числом обучающих заходов.

Модели для обучения: Ridge, Huber, ElasticNet и Polynomial Ridge второй степени. Базовый прогноз сохраняет текущую вертикальную скорость. Все модели учат поправку к нему. Подбор параметров компактный: три варианта на семейство, по валидационным дням; проверочные дни не участвуют в выборе модели.

В каждом сезоне последние два выбранных дня используются для теста, предыдущий для валидации, остальные для обучения. Есть отдельное обучение по сезонам и общее обучение. Межсезонный перенос является сравнением на отложенных днях; общее обучение использует разные месяцы года. Один борт может встречаться в разных днях; его идентификатор не является признаком.

Для кривой обучения сравниваем Ridge и Polynomial Ridge на 1, 2, 3, 5 днях и полном доступном обучающем наборе. Повторяем выбор вложенных наборов три раза. Основной вариант берет одинаковое число заходов каждого дня; контроль разнообразия сохраняет тот же бюджет суммарно, распределяя его между днями. Бюджет вычисляется по доступным обучающим дням, не больше 30 заходов; тестовые ошибки на него не влияют. Параметры модели фиксируются после выбора по валидации полного обучающего набора сезона. Каждый заход имеет одинаковый суммарный вес независимо от числа пар наблюдений.

## Какие дни ищем

Одна полоса: LFPG 09L. Полосу определяем по фактическим траекториям, а не по направлению ветра. Берем дни с десятками пригодных заходов в дневном интервале с хорошей погодой. Правила высотного прогноза сохраняются: история 5–30 секунд, горизонт 30 ± 3 секунды, наблюдения до барометрического прокси 300 ft.

Рабочее определение хорошей погоды для исследования: видимость не менее 10 км, нижняя граница BKN/OVC не ниже 3000 ft или CAVOK, ветер не выше 15 kt, порывы не выше 25 kt, температура от -10 до +30 C. Исключаем осадки, грозы, туман, пыльные/песчаные явления и сообщения о сдвиге ветра. Условия проверяются по наблюдаемой части METAR, без использования TEMPO/BECMG как фактических наблюдений. Это условия отбора исследовательской группы, а не эксплуатационные минимумы.

Для дневного поиска используем 08:00–18:00 местного времени Парижа с учетом перехода на летнее время. По указанию пользователя нужен целиком погожий день: хорошая погода должна покрывать весь этот интервал; каждый включенный заход целиком проходит в подходящей погоде. Погодные интервалы с неизвестными условиями исключаем. Дни сезона считаются найденными только после проверки достаточного числа заходов.

## Данные и результаты

- `data/`: исходные METAR, локальные архивы, отобранные траектории и обучающие примеры; исключены из Git
- `notebooks/`: выполненный обзор поиска дней и дальнейшие обучающие эксперименты
- `reports/`: итоговые таблицы выбранных дней и результатов моделей
- `figures/`: рисунки для ноутбуков
- `scripts/`: получение и подготовка данных

Источники: [ADSB.lol, архив 2025](https://github.com/adsblol/globe_history_2025), [METAR IEM](https://mesonet.agron.iastate.edu/request/download.phtml). Геометрия полос и причинные признаки продолжают предыдущую работу LFPG; происхождение новых исходных файлов хранится рядом с данными.

Дата поиска не выбирается по ошибкам моделей. Неподходящие дни не оформляются в отдельные отчеты. Для последующего обучения нужны сначала подтвержденные 30 дней трех выбранных сезонов. Очередь погодных кандидатов упорядочена по доле времени с восточным ветром для ускорения поиска; фактическая полоса проверяется по траекториям. Три сезона собираются одновременно, поиск каждого прекращается после десяти готовых дней.

## Что получилось при проверке погоды

Проверка всех месяцев 2025 года дала следующие погодные кандидаты для дневного интервала 08:00–18:00:

| Сезон | Погодных кандидатов | Нужно дней с заходами на 09L |
|---|---:|---:|
| Зима | 10 | Оставлена вне нового расчета |
| Весна | 29 | 10 |
| Лето | 45 | 10 |
| Осень | 18 | 10 |

Это предварительный отбор: заходы на 09L и их достаточное количество проверяются отдельно. Новый набор из 30 дней пока собирается; сезонный расчет еще не запускался. Зимний пилот выполнен, его результаты приведены ниже.

Проверка архива за 1 декабря исключила один зимний кандидат: в дневном интервале найдено 69 геометрических заходов на 26L и ни одного на 09L. Поэтому для зимы остается максимум девять дней еще до проверки остальных кандидатов. По решению пользователя цель для зимней группы теперь девять дней; остальные кандидаты проверяем по траекториям.

## Повторить расчет

Из корня репозитория установить зависимости `python -m pip install -r research/lfpg-seasonal-learning/requirements.txt`, затем выполнить `python research/lfpg-seasonal-learning/scripts/select_weather.py 2025`. Скрипт загружает METAR IEM, сохраняет исходные сообщения и таблицу погодных кандидатов в локальной папке `data/`. При повторном запуске используются сохраненные исходные сообщения.

Для проверки фактических заходов выполнить `python research/lfpg-seasonal-learning/scripts/collect_days.py YYYY-MM-DD`. Суточный архив ADSB.lol занимает несколько гигабайт; исходные файлы, их контрольные суммы и извлеченные траектории сохраняются локально в `data/`.

`python research/lfpg-seasonal-learning/scripts/prepare_examples.py YYYY-MM-DD` строит наблюдаемые обучающие пары по прежним причинным признакам. `python research/lfpg-seasonal-learning/scripts/collect_seasons.py` собирает по десять готовых дней весны, лета и осени. После подтверждения всех дней `python research/lfpg-seasonal-learning/scripts/train_models.py` запускает обучение трех сезонов и сохраняет итоговую таблицу, сравнение переноса между сезонами и кривые обучения. При нехватке подтвержденных дней обучение не начинается.

`python research/lfpg-seasonal-learning/scripts/build_training_notebook.py` выполняет ноутбук с таблицей и рисунками после завершенного обучения.
